# Документація промптів

Усі промпти лежать у `ai_analyst/prompts.py`. Загальні принципи для всіх функцій:

- **Pandas рахує, LLM інтерпретує.** Модель отримує готові числа й не має права їх перераховувати: у загальному системному промпті стоїть «використовуй цифри з фактів дослівно».
- **Структурований вихід.** Скрізь вимагається JSON із фіксованою схемою, тому відповідь парситься програмно (`ask_json`); при невалідному JSON запит повторюється один раз.
- **Температура 0.** Результати відтворювані, що важливо для тестування.
- **Перевірка після відповіді.** Кожне число у відповіді звіряється з вхідними фактами (`verify.py`); невідповідності виводяться як попередження.
- **Мова.** Відповіді українською, бо звіти й дані для україномовного користувача.

## 1. SYSTEM_BASE (спільна основа)

Роль («досвідчений продуктовий аналітик»), заборона вигадувати числа, мова. Роль задає рівень відповіді; заборона є основним захистом від галюцинацій, а `verify.py` її перевіряє.

## 2. EDA_SYSTEM

Вхід: профіль таблиці (JSON). Вихід: `quality_summary`, `issues` (колонка, проблема, severity, evidence), `key_findings`, `next_steps`.
Чому так: поле `evidence` змушує прив'язувати кожну проблему до цифри з профілю, тоді її можна перевірити. Окремо вказано, що за відсутності проблем `issues` має бути порожнім, щоб модель не вигадувала проблеми «для повноти».

## 3. NL2PANDAS_SYSTEM та NL2PANDAS_FIX

Вхід: схема таблиць (колонки, типи, 2 приклади рядків) і питання. Вихід: `code` та `explanation`.
Чому так:
- у схему додано приклади рядків, щоб модель бачила формат значень (наприклад, повні назви країн замість кодів);
- результат завжди у змінній `result`, це дає єдину точку виходу для виконання;
- заборони (імпорти, файли, eval) продубльовано і в промпті, і в статичній перевірці коду (`check_code`), бо промпту недостатньо для безпеки;
- поле `code: null` дозволяє моделі відхиляти нелогічні питання замість вигадування колонок;
- NL2PANDAS_FIX: у разі помилки модель отримує текст помилки і свій код та має один раз його виправити.

## 4. ANOMALY_SYSTEM

Вхід: порівняння двох періодів та внески сегментів, пораховані `decompose`. Вихід: `headline`, `top_drivers`, `hypotheses` (з `evidence` та `how_to_check`), `confidence`.
Чому так: модель не шукає сегменти сама, цю частину рахує pandas, тому LLM не може пропустити чи вигадати драйвер. Вимога «гіпотеза, а не доведена причина» і поле `how_to_check` роблять висновок придатним до перевірки; `confidence` просить модель оцінити власну впевненість.

## 5. SUMMARY_SYSTEM

Вхід: KPI двох періодів і відсоткові зміни. Вихід: `what_happened`, `why_it_matters`, `recommendations`, `risks`.
Чому так: структура що сталося, чому важливо, що робити повторює вимоги до summary зі стейкхолдерами; поле `risks` змушує згадати обмеження даних.
