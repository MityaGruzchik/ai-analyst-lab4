# AI-асистент аналітика

Консольний Python-інструмент, який скорочує рутинну частину роботи продуктового аналітика. Усі числа (профіль даних, внески сегментів, KPI) рахує pandas, а LLM (за замовчуванням Llama через Groq, підходить будь-який OpenAI-сумісний API) тільки інтерпретує готові цифри, формулює гіпотези та пише текст. Кожну відповідь моделі, що містить число, яких немає у вхідних фактах, інструмент позначає як можливу галюцинацію.

Інструмент протестовано на реальному датасеті мобільного застосунку (квітень-травень 2024): 202 382 реєстрації, 11 330 платежів, довідник країн. Той самий набір використано в лабораторних 2 і 3.

## Реалізовані функції

1. **Автоматичний EDA** (`eda`): типи колонок, пропуски, дублікати, викиди за IQR, топ-значення рахує pandas; LLM повертає JSON із оцінкою якості даних, проблемами (з цифрою-доказом) і наступними кроками.
2. **Natural Language to Pandas** (`ask`): питання природною мовою перетворюється на код pandas. Код завжди показується користувачу, перед запуском проходить статичну перевірку (без імпортів, файлів, eval/open, dunder-атрибутів), виконується у обмеженому середовищі; при помилці модель один раз виправляє код. Нелогічні питання (немає потрібних колонок) модель відхиляє.
3. **Пояснення змін метрики** (`explain`): pandas порівнює виручку у двох періодах і рахує внесок кожної країни, платформи та типу покупки у зміну; LLM формулює 2-4 гіпотези причин із цифрами з розрахунку.
4. **Executive summary** (`summary`): pandas рахує KPI (нові користувачі, виручка, платники, середній чек) за два періоди; LLM пише короткий текст для стейкхолдера: що сталося, чому важливо, що робити.

## Технології

Python 3.10+, pandas, numpy, OpenAI-сумісний LLM API, за замовчуванням Groq (REST, через стандартну бібліотеку), pytest.

## Запуск

```bash
git clone https://github.com/MityaGruzchik/ai-analyst-lab4.git
cd ai-analyst-lab4
pip install -r requirements.txt
```

API-ключ: безкоштовно створи його в Groq Console (console.groq.com, розділ API Keys) і задай як змінну середовища:

```bash
export LLM_API_KEY="gsk_..."        # Linux / macOS
$env:LLM_API_KEY = "gsk_..."        # Windows PowerShell
```

Модель за замовчуванням `openai/gpt-oss-120b`; змінити можна змінною `AI_ANALYST_MODEL`. Інший сервіс (OpenRouter, Mistral, локальна Ollama) підключається змінною `LLM_BASE_URL`, наприклад `http://localhost:11434/v1` для Ollama.

Приклади команд (демо-датасет вже лежить у `data/`):

```bash
python -m ai_analyst eda --table payments
python -m ai_analyst ask "Покажи топ-10 країн за виручкою"
python -m ai_analyst explain --base 2024-04-15 2024-04-21 --target 2024-04-22 2024-04-28
python -m ai_analyst summary --base 2024-04-15 2024-04-21 --target 2024-04-22 2024-04-28
```

Для власного файлу додай `--csv шлях/до/файлу.csv` перед командою (працюють `eda` і `ask`; колонки з суфіксом `_dt` розпізнаються як дати).

## Тести

```bash
python -m pytest -q
```

Тести (12) перевіряють розрахунки, безпеку виконання коду, парсинг JSON, відхилення нелогічних запитів, виправлення помилок і виявлення вигаданих чисел. Замість LLM у тестах використовується підставка, тому API-ключ не потрібен.

## Демонстрація на реальних даних

Розрахунки, які отримує LLM на вході у командах `explain` і `summary` (період 15-21 квітня проти 22-28 квітня 2024):

- виручка зросла з 13 972,71 до 25 022,06 $ (+79,08%);
- найбільший внесок у зміну дали Україна (+2 264,33 $, 20,5% зміни), Південна Африка (+1 174,33 $) і Казахстан (+907,17 $);
- за платформою вся зміна пояснюється mobile (+12 075,56 $), ios просів на 1 154,07 $;
- нові користувачі зросли на 58,5%, платники на 100,1%, середній чек знизився на 6,5% (з 8,66 до 8,10 $).

Запит `ask "Покажи топ-10 країн за виручкою"` повертає таблицю, де на першому місці Україна (22 954,52 $), далі США (19 141,17 $) і Південна Африка (6 053,40 $): ці числа збігаються з дашбордом із лабораторної 3.

Повний прогін усіх функцій на цих даних зроблено в `demo.ipynb`, вивід усіх комірок збережено в ньому.

## Структура

```

tests/        тести

```

## Обмеження

- Якість висновків залежить від моделі; гіпотези про причини залишаються гіпотезами, їх треба перевіряти.
- Перевірка чисел ловить вигадані цифри, але не перевіряє логіку висновків.
- Обмежене середовище для виконання коду зменшує, але не прибирає ризик: для довірених даних і локального запуску цього достатньо, для публічного сервісу треба ізоляція в контейнері.
